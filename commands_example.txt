Формат бинарного протокола Fogel Adapter
========================================

## Формат фрейма

Каждый фрейм имеет структуру:
  [2 байта: длина payload + 1 (type)] [1 байт: тип сообщения] [payload]

Длина (length) включает байт типа, но НЕ включает 2 байта самой длины.
Максимальный размер payload: 512 байт.

## Порты

  TCP: 8888 — команды, ответы, TICK-сообщения (BMS данные)
  UDP: 8889 — высокочастотные CAN-фреймы (21 байт на фрейм)

## Константы типов сообщений (client → ESP32)

| Код | Имя              | Назначение                                   |
|-----|------------------|----------------------------------------------|
| 0x01 | MSG_PING        | Проверка соединения                          |
| 0x02 | MSG_TICK_OK     | (зарезервирован, не используется)            |
| 0x03 | MSG_GET_CONFIG  | Запрос глобальной конфигурации               |
| 0x04 | MSG_GET_PROTOCOL| Запрос деталей протокола                     |
| 0x05 | MSG_SET_CAN_SPEED| Установка скорости CAN (или AUTO=0xFFFFFFFF) |
| 0x06 | MSG_SET_PROTOCOL | Установка активного протокола (0 байт = сброс)|
| 0x07 | MSG_CMD          | Отправка команды контактора                  |
| 0x08 | MSG_UDP_REG      | Регистрация UDP-порта для CAN-фреймов        |
| 0x09 | MSG_CAN_CLEAR    | Сброс статистики CAN                         |

## Константы типов сообщений (ESP32 → client)

| Код | Имя              | Назначение                                   |
|-----|------------------|----------------------------------------------|
| 0x81 | MSG_PONG        | Ответ на PING                                |
| 0x82 | MSG_OK          | Успех                                        |
| 0x83 | MSG_FAIL        | Ошибка                                       |
| 0x84 | MSG_CONFIG      | Глобальная конфигурация                      |
| 0x85 | MSG_PROTOCOL_DTL| Детали протокола                             |
| 0x86 | MSG_SPEED_RESULT| Результат установки скорости CAN             |
| 0x87 | MSG_PROTO_RESULT| Результат установки протокола                |
| 0x88 | MSG_TICK        | Периодический статус (BMS + CAN-статистика)  |

## Жизненный цикл подключения

1. WiFi: подключение к точке доступа Fogel Adapter (SSID: "Fogel Adapter XX")
2. TCP: Socket.connect("192.168.4.1", 8888)
3. UDP: RawDatagramSocket.bind(AnyIPv4, 8889)
4. Отправить MSG_UDP_REG с портом 8889 (2 байта, big-endian)
5. Отправить MSG_PING
6. Получить MSG_PONG
7. Отправить MSG_GET_CONFIG
8. Получить MSG_CONFIG → установить скорость CAN по умолчанию
9. Начинают поступать MSG_TICK каждые 500 мс и CAN-фреймы по UDP

## Раскладки payload по типам сообщений

### MSG_GET_CONFIG (0x03)
Пустой payload.

### MSG_CONFIG (0x84)
  [2 байта: кол-во протоколов]
  Для каждого протокола:
    [1 байт: длина имени N] [N байт: имя протокола]
  [2 байта: кол-во скоростей CAN]
  Для каждой скорости:
    [4 байта: скорость в kbps, big-endian uint32]
  [4 байта: скорость CAN по умолчанию, big-endian uint32]
  [1 байт: поддержка AUTO (1 = есть)]

Пример (бинарный):
  00 03        # 3 протокола
  0C D0 94 D0 A1 D0 A2 20 D0 90 D0 9A D0 91 20 E2 84 9611  # "ДСТ АКБ №1" (12 байт UTF-8 + длина)
  0C D0 94 D0 A1 D0 A2 20 D0 90 D0 9A D0 91 20 E2 84 9612  # "ДСТ АКБ №2"
  04 48 45 4C 49                                            # "HELI" (4 байта)
  00 08        # 8 скоростей
  00 00 00 19  # 25 kbps
  00 00 00 32  # 50 kbps
  00 00 00 64  # 100 kbps
  00 00 00 7D  # 125 kbps
  00 00 00 FA  # 250 kbps
  00 00 01 F4  # 500 kbps
  00 00 03 20  # 800 kbps
  00 00 03 E8  # 1000 kbps
  00 00 00 FA  # default = 250 kbps
  01           # has auto = true

### MSG_GET_PROTOCOL (0x04)
  [1 байт: длина имени] [N байт: имя протокола в UTF-8]

### MSG_PROTOCOL_DTL (0x85)
  [1 байт: длина имени] [N байт: имя]
  [4 байта: скорость CAN, uint32]
  [2 байта: длина строки params] [N байт: params]
  [2 байта: длина строки commands] [N байт: commands]

### MSG_SET_CAN_SPEED (0x05)
  [4 байта: скорость в kbps, big-endian uint32]
  Специальное значение 0xFFFFFFFF = AUTO (автоопределение скорости)

### MSG_SPEED_RESULT (0x86)
  [4 байта: скорость в kbps, big-endian uint32]

### MSG_SET_PROTOCOL (0x06)
  [1 байт: длина имени] [N байт: имя протокола в UTF-8]
  Длина 0 = сброс протокола (NULL)

### MSG_PROTO_RESULT (0x87)
  [1 байт: длина имени] [N байт: имя протокола]
  Длина 0 = протокол сброшен

### MSG_CMD (0x07)
  [1 байт: длина команды] [N байт: тип команды] [1 байт: значение (0/1)]
  Команды: "CHARGE", "DISCHARGE", "PRECHARGE"

### MSG_TICK (0x88) — периодический статус
  [2 байта: напряжение АКБ, int16 * 10, 0x7FFF = null]
  [2 байта: SOC (заряд), int16, 0x8000 = null]
  [2 байта: температура, int16 * 10, 0x7FFF = null]
  [2 байта: ток заряда, int16 * 10, 0x7FFF = null]
  [2 байта: ток разряда, int16 * 10, 0x7FFF = null]
  [1 байт: флаги]
    bit 0 = CHARGE ON
    bit 1 = DISCHARGE ON
    bit 2 = PRECHARGE ON
  [4 байта: всего CAN-сообщений, uint32]
  [4 байта: уникальных CAN-ID, uint32]
  [1 байт: кол-во ячеек]
  Для каждой ячейки:
    [2 байта: напряжение ячейки, uint16 * 100]

### MSG_UDP_REG (0x08)
  [2 байта: UDP-порт клиента, big-endian uint16]

### MSG_CAN_CLEAR (0x09)
  Пустой payload.

## Формат CAN-фрейма (UDP, 21 байт)

  [4 байта: CAN ID, big-endian uint32]
  [1 байт: DLC (0-8)]
  [8 байт: данные CAN (неиспользуемые байты заполнены нулями)]
  [4 байта: период сообщения в мс, uint32]
  [4 байта: счётчик сообщений с этим ID, uint32]

Пример: ID=0x18FEF100, DLC=8, данные=00:11:22:33:44:55:66:77, период=15мс, счётчик=528
  18 FE F1 00 08 00 11 22 33 44 55 66 77 00 00 00 0F 00 00 02 10
